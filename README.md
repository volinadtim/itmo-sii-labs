## Запуск

Python 3.12. Из корня репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Откройте нужный ноутбук и выберите Restart Kernel and Run All Cells. ЛР1 и ЛР2 ожидают рабочую папку своего ноутбука (обычное поведение Jupyter); ЛР3 также поддерживает запуск из корня.

## Результаты ЛР3

Проверено полное выполнение ноутбука (11 кодовых ячеек, без ошибок), сохранение всех 6 текстовых ячеек шаблона, контрольная сумма CSV, непересечение train/test и независимый пересчёт 21 метрики по сохранённым предсказаниям.

| Модель | Balanced accuracy | Precision | Recall | F1 | ROC AUC |
|---|---:|---:|---:|---:|---:|
| Константная | 0.500 | 0.000 | 0.000 | 0.000 | 0.500 |
| LogisticRegression, C=1 | 0.894 | 0.729 | 0.887 | 0.800 | 0.965 |
| SVC linear, C=1 | 0.893 | 0.725 | 0.888 | 0.798 | 0.965 |

Train: 13 832, test: 3 458. На CV включение balanced у SVC подняло recall с 0.784 до 0.911, снизив precision с 0.854 до 0.712. Это ожидаемый обмен числа пропусков дорогих объектов на ложные срабатывания. Отличия моделей на test малы; статистическое превосходство не установлено.

OneClassSVM с nu=0.05 отметил 188 из 3 458 тестовых объявлений (5.44%). Это кандидаты на проверку, не подтверждённые ошибки данных.

Задание 3: macro=29/36≈0.805556, weighted=3/4, micro=5/6≈0.833333, samples=7/8. Все четыре оценки совпадают со слайдом после округления. Для каждого класса AUC посчитан и через пары score, и по площадям трапеций вручную.

В примере из четырех объектов не удается получить три разных accuracy без неопределенной precision; эта особенность разобрана явно. Для трех разных значений всех метрик дополнительно приведен расчет по фиксированным score-порогам −1, 0, 1 на квартирах, без подбора лучшего порога по test.
